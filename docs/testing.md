# 测试范围与已知限制

## 可以确认的范围

仓库的 GitHub Actions 配置使用 Node.js 24，在 `macos-latest`、`windows-latest` 和 `ubuntu-latest` runner 上执行语法检查、模块／文件操作测试与两个平台 ZIP 的打包检查。每次运行是否通过，以该提交关联的 [Actions 结果](https://github.com/youngerweb2026/codex-sidebar-tools/actions)为准；工作流存在不等于某次运行已经通过。

模块测试的用途包括日期边界、额度窗口与倒计时、状态保存、便签冲突、入口输入限制及平台路径／命令构造。更新恢复测试使用临时目录和模拟进程／启动适配器，检查待办持久化、应用替换、路径变化、退出交接、重复启动防护和普通退出行为。它们不能代替用户账号和桌面客户端的完整验收。

## 不应推断的结论

- Windows runner 没有带登录账号的 Codex 桌面交互环境；Windows 侧栏 UI、登录环境、Store 包更新及不同系统配置仍需实机验证。
- Linux runner 用于测试可移植代码，不代表发布 Linux 桌面版本。
- README 的截图为 macOS 界面示例，不是 Windows 截图，也不证明所有账号都返回相同额度窗口。
- 原项目 v0.9.4 的验证记录不自动适用于此独立版本。
- 发布成功、安装命令退出成功、后台进程存活和侧栏真实显示是不同的验收阶段。

## 建议的实机验收

1. 保存工作并自行退出客户端，通过本项目入口打开。
2. 确认仅有“入口”“便签”两个工具按钮，会员与额度区域不重叠。
3. 设置自己的会员日期，核对按北京时间计算的剩余天数。
4. 确认额度有当前可用读数；额度详情只在额度区域悬停时出现。
5. 添加、编辑、移除一个测试入口，确认网页进入 Chrome、文件夹能打开。
6. 保存一条测试便签，切换聊天并重新打开后核对；测试多窗口冲突时确认草稿未丢失。
7. 检查浅色和深色、较小窗口以及客户端更新后的显示。
8. 在缺少本机连接的活动窗口运行“恢复插件”，确认窗口不被结束；完全退出后确认只自动重新打开一次，再次正常退出应保持关闭。
9. 安装新插件版本前后核对会员日期、便签和快捷入口；更新客户端后确认后台重新连接并保持这些数据。
10. 运行诊断并检查卸载只影响本项目，其他插件和客户端文件保持原样。

报告失败时提供客户端版本、系统版本和复现步骤；不要提交密钥、账号登录文件、私人便签或完整原始日志。
